Example N10: using.cpp

examples/N10_use_of_using/using.cpp

#include<iostream>
template <typename ntype>
class base {
public:
  void funcbase(void)
    {
      std::cout << "hallo ";
    }
  ntype a;
};

template <typename ntype>
class derived: public base<ntype> {
public:
  using bt = base<ntype>; // this is just an alias (from c++11 on, i.e. use at least -std=c++11 to compile)
  using base<ntype>::a, bt::funcbase; // if we remove this we got a compilation error
  void funcder(void)
    {
      funcbase();
      std::cout << "from derived: " << a << "\n";
    }
  derived(ntype x) // constructor
    {
      a = x;
    }
};

int main(void)
{
  derived<double> A(1.1);
  A.funcder();
  return 0;
}

Example N10: how it works

g++ -std=c++17 -Wall -o using using.cpp && ./using     # prints: hallo from derived: 1.1
  • derived<ntype> inherits from base<ntype>, which depends on the template parameter. When the compiler reads the template, base<ntype> is not a class yet: it is created when the template is instantiated (derived<double> creates base<double>), and for some ntype it could be replaced by a specialization, a different definition with other members. So a name written alone, like funcbase or a, is not looked up there.
  • Comment out line 16: error: there are no arguments to 'funcbase' that depend on a template parameter, so a declaration of 'funcbase' must be available (line 19) and error: 'a' was not declared in this scope (lines 20 and 24).
  • Line 16 says that a and funcbase come from the base class. Alternatives: this->a and this->funcbase(), or base<ntype>::a and base<ntype>::funcbase().
  • using bt = base<ntype>; (line 15): an alias; the comma in line 16 needs C++17.
  • With a base class that is not a template (example N2) none of this is needed.

#include<iostream>

class particle
{
  ntype rx, ry, rz;

    {
      std::cout << "particle position is (" << rx << "," << ry << "," << rz << ")\n";
    }

    }

{
  using pt = particle<double>; // using to define an alias
  std::vector<pt> p; // vector of particles

  p[0].set_pos(1,2,3);

  p[1].show();

}

Example N12: composition.cpp

examples/N12_composition/composition.cpp

#include<iostream>
class Acl
{
  double da;
public:
  Acl() // constructor
    {
      da = 1.0;
    }
  void showA(void)
    {
      std::cout << da << "\n";
    }
};

class Bcl
{
  // same name as in Acl: Derive inherits both, Acl::da and Bcl::da,
  // so D.da would not compile ("request for member 'da' is ambiguous")
  double da;
public:
  Bcl() // constructor
    {
      da = 2.0;
    }
  void showB(void)
    {
      std::cout << da << "\n";
    } 
};
class Compose // COMPOSITION
{
  int c;
public:
  Acl A;
  Bcl B;
};

class Derive: public Acl, public Bcl // DERIVATION
{
  int c;
public:
};


int main(void)
{
  Derive D;
  Compose C;
  D.showA();
  D.showB();
  C.A.showA();
  C.B.showB();
  //C.B.showA();
}

Example N12: how it works

g++ -std=c++17 -Wall -o composition composition.cpp && ./composition    # prints 1 2 1 2
  • Compose has an Acl and a Bcl, its members A and B: this is composition. Derive is an Acl and is a Bcl: this is multiple inheritance, a class derived from two classes.
  • D.showA() and D.showB() are inherited; C.A.showA() and C.B.showB() go through the members. C.B.showA() (line 55) does not compile: B is only a Bcl, error: 'class Bcl' has no member named 'showA'; did you mean 'showB'?
  • Both base classes have a member da: D contains two of them, and D.da gives error: request for member 'da' is ambiguous (besides error: 'double Acl::da' is private within this context). If both classes had a method show(), D.show() would be ambiguous too, and D.Acl::show() would choose. With composition there is no clash: C.A and C.B are two separate objects.
  • A rule of thumb: inheritance for “is a” (a Lennard-Jones particle is a particle), composition for “has a” (a particle has a position, a pvector).

Task 1 and random(L)

project/pvector.hpp

// STRATEGIES TO MAKE CLASS GENERIC
//#define NT 3
// constexpr tells compiler that NT can be calculated at compile time
//constexpr int NT=3;

//typedef float ntype; // as in C
//using ntype=double; // use "using" to define an alias for the keyword "double"

template <typename ntype, int NT>
class pvector
{
  ntype v[NT]; // private member
  // generate a random vector inside a box and assign it to (*this) object
  void random(const ntype& L)
    {
      for (int i=0; i < NT; i++)
        {
          v[i] = (rng.ranf()-0.5)*L; // assign a random value in [-L/2,L/2)
        }
    }
  • Task 1: NT and ntype commented out, template <typename ntype, int NT> before class pvector; in pvector.cpp, pvector<ntype,NT> R, U;.
  • random(L): (rng.ranf()-0.5)*L is uniform in \([-L/2, L/2)\), one number for each component (rng: the generator of randnumgen.hpp).

random_orient()

project/pvector.hpp

  // generate a random vector on unit sphere and assign it to (*this) object
  void random_orient(void)
    {
      ntype rS, S, V1, V2;
      if (NT==3)
        {
          do
            {
              V1 = 2.0*rng.ranf()-1.0;
              V2 = 2.0*rng.ranf()-1.0;
              S = V1*V1+V2*V2;
            }
          while (S >= 1.0);
          rS = sqrt(1.0-S);
          v[0] = 2.0*rS*V1;
          v[1] = 2.0*rS*V2;
          v[2] = 1.0-2.0*S;
        }
      else
        {
          std::cout << "[random_orient] Only 3D vectors are supported\n";
        }
    }
  • do ... while: steps 1 and 2 of Marsaglia’s algorithm (the rejection), then step 3.
  • With (*this) = {2.0*rS*V1, 2.0*rS*V2, 1.0-2.0*S}; and pvector<float,3>: warning: narrowing conversion ... from 'double' to 'float', since 2.0 is a double; v[0] = ... converts silently.

pmatrixq: the constructors (1)

project/pmatrix.hpp

  pmatrixq()
    {
      for (int i=0; i < NT; i++)
        for (int j=0; j < NT; j++)
          m[i][j]=0;
    }

  // to initialize a matrix as follows: pmatrixq<double,2> M={1,2,3,4};
  pmatrixq(std::initializer_list<ntype> list)
    {
      int cc=0;
      for (auto el: list)
        {
          if (cc < NT*NT)
            m[cc/NT][cc%NT] = el;
          cc++;  
        }
      for ( ; cc < NT*NT; cc++) // shorter list: the others are 0
        m[cc/NT][cc%NT] = 0;
    }
  • {1,2,...}: the element number cc goes to m[cc/NT][cc%NT], only if cc < NT*NT; with a shorter list the other elements are set to 0, as in the constructor of pvector (Lab #2).

pmatrixq: the constructors (2)

project/pmatrix.hpp

  // to initialize a matrix as follows: pmatrixq<double,2> M={{1,2},{3,4}};
  pmatrixq(std::initializer_list<std::initializer_list<ntype>> list)
    {
      for (int i=0; i < NT; i++) // first all 0: missing ones stay 0
        for (int j=0; j < NT; j++)
          m[i][j]=0;
      int i=0, j=0;
      for (auto r: list)
        {
          j=0;
          for (auto c: r)
            {
              if (i < NT && j < NT)
                m[i][j] = c;
              j++;
            }
          i++;
        }
    }
  • {{...},{...}}: first all the elements to 0, then two nested range-based for, over the rows and over the elements of each row; if (i < NT && j < NT) never writes outside m. So pmatrixq<double,3> M = {{1,2},{3}}; gives {{1,2,0},{3,0,0},{0,0,0}}.

  // ============================================================
  // overloading of () operator to get/set (i,j)-th element
  // m(i,j)=2.0;
  // std::cout << m(i, j);
  ntype& operator()(int i, int j)
    {
      return m[i][j];
     }
  
  ntype operator()(int i, int j) const
    {
      return m[i][j];
    }

  // output (std::cout << M) << "\n";
  friend std::ostream& operator<<(std::ostream& os, const pmatrixq& M1)
    {
      int i, j;
      os << "{";
      for (i=0; i < NT; i++)
        {
          os << "{";
          for (j=0; j < NT; j++)
            {
              os << M1(i,j);
              if (j < NT-1)
                os << ",";
            }
          os << "}";
          if (i < NT-1)
            os << ",";
        }
      os << "}";
      return os;
    }
  // addition 
  pmatrixq operator+(const pmatrixq &M2) const
    {
      // MT = M1 + M2
      pmatrixq MT;
      for (auto i=0; i < NT; i++)
        {
          for (auto j=0; j < NT; j++)
            {
              MT(i,j) = (*this)(i,j) + M2(i,j);
            }
        }
      return MT;
    }
  // subtraction
  pmatrixq operator-(const pmatrixq &M2) const
    {
      // MT = M1 - M2
      pmatrixq MT;
      for (auto i=0; i < NT; i++)
        {
          for (auto j=0; j < NT; j++)
            {
              MT(i,j) = (*this)(i,j) - M2(i,j);
            }
        }
      return MT;
    }

Hints: assignments and scalars

  • M1 += M2 changes M1 and returns it by reference, return (*this);, like operator= of pvector. It can reuse +: *this = *this + M2;. The same for -=.
  • *= and /= with a scalar: two nested loops on m[i][j], then return (*this);.
  • M*s and M/s do not change M: const methods with a local MT, returned by value, like + and -.
  • s*M: the left operand is not a pmatrixq, so it cannot be a method. It is a friend function with two arguments, like “scalar times vector” in pvector (Lab #3), and it can reuse M2*s.
  • operator* has five versions, M*s, s*M, M*V, V*M and M1*M2: the compiler chooses the right one from the types of the operands (overloading, Lab #2).

Hints: products, transpose and ==

  • In formulas: \[(MV)_i = \sum_j M_{ij} V_j \qquad (VM)_j = \sum_i V_i M_{ij} \qquad (M_1 M_2)_{ij} = \sum_k (M_1)_{ik} (M_2)_{kj}\] Each sum is a loop, inside the loops over the free indices: set the sum to 0 first.
  • V*M is a friend of pmatrixq, not of pvector: it can read M2.m, but not V1.v. Use V1(i), otherwise error: 'double pvector<double, 3>::v [3]' is private within this context.
  • M1 *= M2: compute the product in a new matrix first, then assign: *this = (*this)*M2; (why: Classic pitfalls).
  • transpose() returns a new matrix, \(M^T_{ij} = M_{ji}\), and does not change M: a const method.
  • ==: return false at the first element that differs, true after the loops.

The goal: pmatrix.cpp

project/pmatrix.cpp

#include "./pmatrix.hpp"
int main(void)
{
  using ntype = double;       // type of the elements
  constexpr int NT = 3;       // size of the matrices
  pmatrixq<ntype,NT> A = {{1, 2, 3}, {4, 5, 6}, {7, 8, 10}};
  pmatrixq<ntype,NT> B = {{2, 0, 1}, {1, 3, 0}, {0, 1, 4}};
  pmatrixq<ntype,NT> C;
  const pmatrixq<ntype,NT> I = {{1, 0, 0}, {0, 1, 0}, {0, 0, 1}};
  pvector<ntype,NT> V = {1, 2, 3};

  std::cout << "A=" << A << "\n";
  std::cout << "B=" << B << "\n";
  std::cout << "A*2=" << A*2.0 << "\n";
  std::cout << "2*A=" << 2.0*A << "\n";
  std::cout << "A/2=" << A/2.0 << "\n";
  C = A;
  C += B;  std::cout << "C=A, C+=B: " << C << "\n";
  C -= B;  std::cout << "C-=B:      " << C << "\n";
  C *= 3.0; std::cout << "C*=3:      " << C << "\n";
  C /= 3.0; std::cout << "C/=3:      " << C << "\n";
  std::cout << "A*V=" << A*V << "\n";
  std::cout << "V*A=" << V*A << "\n";
  std::cout << "A*B=" << A*B << "\n";
  std::cout << "B*A=" << B*A << "\n";          // the product is not commutative
  C = A;
  C *= B;  std::cout << "C=A, C*=B: " << C << "\n";
  std::cout << "transpose(A)=" << A.transpose() << "\n";
  std::cout << "A*I==A: " << (A*I == A) << "  I*A==A: " << (I*A == A)
            << "  A==B: " << (A == B) << "\n";
  std::cout << "(A*B)^T==B^T*A^T: "
            << ((A*B).transpose() == B.transpose()*A.transpose()) << "\n";
  return 0;
}

Classic pitfalls

  • A missing const, e.g. on M1*M2: then I*A, with I declared const, gives error: passing 'const pmatrixq<double, 3>' as 'this' argument discards qualifiers.
  • s*M as a method: an operator method has one explicit operand, the other is *this: error: '... operator*(const ntype&, const pmatrixq<ntype, NT>&)' must have either zero or one argument.
  • The product in place: writing m[i][j] while row i is being computed uses the new m[i][0] to compute m[i][1]: C=A; C*=B; gives {{4,9,16},{13,21,37},{22,34,62}} instead of {{4,9,13},{13,21,28},{22,34,47}}.
  • Swapped indices, e.g. M2(j,k) instead of M2(k,j): it compiles and runs, the expected output catches it.
  • == between double: the comparison is exact. (A*0.1)*10.0 == A is false, because 3*0.1*10 gives 3.0000000000000004. Fine for our tests, with integer elements; in general, compare with a tolerance.
