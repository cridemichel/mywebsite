Example N13: novirtfunc.cpp

examples/N13_virtual_functions/novirtfunc.cpp

#include<iostream>

// BASE CLASS
class base
{
  void no_virt_func(char *txt) // no_virt_func() is not virtual!!!
    {
      std::cout << txt << " - method no_virt_func() of BASE class.\n";
    }
public:
  void printmsg(char* txt)
    {
      no_virt_func(txt);
    }

};

// DERIVED CLASS
class derived: public base
{
  void no_virt_func(char *txt)  // no_virt_func() is redefined but it is not virtual!!!
    {
      std::cout << txt << " - method no_virt_func() of DERIVED class.\n";
    }
public: 
};

int main(int argc, char **argv)
{
  char txt[2][256]={" hallo from object OA!", " hallo from object OB!"};
  base OA;
  derived OB;

  // OA is an instance of the base class
  OA.printmsg(txt[0]);

  // OB is an instance of the derived class
  OB.printmsg(txt[1]); // printmsg (which is a method of base class) calls no_virt_func()
                       // of base class and not the one in the derived class,
                       // even though OB is an instance of "derived" class
  return 0;

Example N13: virtfunc.cpp

examples/N13_virtual_functions/virtfunc.cpp

#include<iostream>

// BASE CLASS
class base
{
  virtual void virt_func(char *txt) // virt_func() is virtual!!!
    {
      std::cout << txt << " - method virt_func() of the BASE class.\n";
    }
public:

  void printmsg(char* txt)
    {
      virt_func(txt);
    }

};

// DERIVED CLASS
class derived: public base
{
  void virt_func(char *txt) override // virt_func() is redefined and it is virtual
    {
      std::cout << txt << " - method virt_func() of the DERIVED class.\n";
    }
public: 
};

int main(int argc, char **argv)
{
  char txt[2][256]={" hallo from object OA!", " hallo from object OB!"};
  base OA;
  derived OB;

  // OA is an instance of base class
  OA.printmsg(txt[0]);

  // OB is an instance of derived class
  OB.printmsg(txt[1]); // printmsg (which is a method of base class) now calls virt_func()
                       // of derived class
  return 0;
}

Example N13: how it works

g++ -std=c++17 -Wall -o novirtfunc novirtfunc.cpp && ./novirtfunc
g++ -std=c++17 -Wall -o virtfunc virtfunc.cpp && ./virtfunc
 hallo from object OA! - method no_virt_func() of BASE class.
 hallo from object OB! - method no_virt_func() of BASE class.
 hallo from object OA! - method virt_func() of the BASE class.
 hallo from object OB! - method virt_func() of the DERIVED class.
  • printmsg() is a method of base. Without virtual, the call no_virt_func(txt) inside it is fixed when base is compiled: it is always the method of base, even for OB. Redefining it in derived does not change what the code of base calls.
  • With virtual, the method to call is chosen at run time, from the type of the object: OB is a derived, so printmsg() calls the virt_func() of derived.
  • override (C++11) asks the compiler to check that the method really replaces a virtual method of the base class. With another signature, e.g. const char *txt, or without virtual in base: error: 'void derived::virt_func(const char*)' marked 'override', but does not override.

Access and overriding

  • virt_func() is private in both classes: derived cannot call the virt_func() of base, but it can override it. Two separate rules decide:
    • access (private, protected, public): who may write the call. The compiler checks it, with the class through which the method is called;
    • virtual: which version runs, chosen at run time from the type of the object.
  • In N13 the call is written in printmsg(), a method of base, which may call its own virt_func(); at run time the version of derived runs, even if it is private too.
  • A public non-virtual method calling a private virtual one is a common pattern: the base class decides when the method is called, the derived classes what it does.

Access and overriding: an example

A method public in the base class and private in the derived one. A reference to base can refer to a derived object (a derived is a base):

class base {
public:
  virtual void f(void) { std::cout << "base::f\n"; }
};
class derived: public base {
  void f(void) override { std::cout << "derived::f\n"; }  // private
};
derived OB;
base& R = OB;
R.f();   // allowed, base::f is public: it prints "derived::f"
OB.f();  // error: 'virtual void derived::f()' is private within this context
  • The same method, derived::f(), can be called through R but not through OB: the access depends on the class used in the call (base or derived), the version that runs on the object (a derived).

  • s*M reuses M*s.

M*V and V*M

project/pmatrix.hpp

  // matrix times vector: (M*V)(i) = sum over j of M(i,j)*V(j)
  pvector<ntype,NT> operator*(const pvector<ntype,NT> &V2) const
    {
      pvector<ntype,NT> VT;
      for (int i=0; i < NT; i++)
        {
          VT(i) = 0.0;
          for (int j=0; j < NT; j++)
            VT(i) += m[i][j]*V2(j);
        }
      return VT;
    }

  // vector times matrix: (V*M)(j) = sum over i of V(i)*M(i,j) (friend function)
  friend pvector<ntype,NT> operator*(const pvector<ntype,NT>& V1, const pmatrixq& M2)
    {
      pvector<ntype,NT> VT;
      for (int j=0; j < NT; j++)
        {
          VT(j) = 0.0;
          for (int i=0; i < NT; i++)
            VT(j) += V1(i)*M2(i,j);
        }
      return VT;
    }
  • The sum is set to 0 before the inner loop. V*M reads the vector with V1(i): it is a friend of pmatrixq, not of pvector.

Is friend needed?

  • s*M and V*M use only public members (M2*s, V1(i), M2(i,j)): friend is not needed for the access, as for mulcw() and divcw() in Lab #4.

  • Inside the class, friend is the way to define a function that is not a method. Outside the class, it becomes a function template:

    template <typename ntype, int NT>
pmatrixq<ntype,NT> operator*(const ntype& s, const pmatrixq<ntype,NT> &M2)
{
  return M2*s;
}

  • The compiler deduces ntype and NT from the arguments, without converting them: 2.0*A works, 2*A does not, error: no match for 'operator*' (operand types are 'int' and 'pmatrixq<double, 3>') and note: deduced conflicting types for parameter 'ntype' ('int' and 'double').

  • The friend defined inside the class is not a template: it is an ordinary function, created together with pmatrixq<double,3>. So 2 is converted to double and 2*A compiles.

Matrix times matrix, transpose, ==

project/pmatrix.hpp

  // matrix times matrix: (M1*M2)(i,j) = sum over k of M1(i,k)*M2(k,j)
  pmatrixq operator*(const pmatrixq &M2) const
    {
      pmatrixq MT;
      for (int i=0; i < NT; i++)
        for (int j=0; j < NT; j++)
          {
            MT(i,j) = 0.0;
            for (int k=0; k < NT; k++)
              MT(i,j) += m[i][k]*M2(k,j);
          }
      return MT;
    }

  // M1 *= M2, i.e. M1 = M1*M2
  pmatrixq& operator*=(const pmatrixq &M2)
    {
      return (*this = (*this)*M2);
    }
  // transpose: MT(i,j) = M(j,i)
  pmatrixq transpose(void) const
    {
      pmatrixq MT;
      for (int i=0; i < NT; i++)
        for (int j=0; j < NT; j++)
          MT(i,j) = m[j][i];
      return MT;
    }

  // M1 == M2: true if all the elements are equal
  bool operator==(const pmatrixq &M2) const
    {
      for (int i=0; i < NT; i++)
        for (int j=0; j < NT; j++)
          if (m[i][j] != M2(i,j))
            return false;
      return true;
    }
  • M1 *= M2 computes the product in a new matrix and then assigns it: in place, the row being computed would use elements already overwritten.
  • == returns false at the first element that differs.

Part 3
The simulation framework

The files of the framework

  • params.hpp: the class simpars<ntype>, all the parameters of a simulation, with their default values set in the constructor.
  • particle.hpp: the class particle<ntype> (position, parameters of the interaction, and what MC and MD need), and particleLJ<ntype>, derived from it, with the Lennard-Jones interaction between two particles.
  • sim.hpp: the class sim<ntype, particle_type>, the part common to Monte Carlo and molecular dynamics. In the next labs mcsim and mdsim will be derived from it.
  • simtest.cpp: today’s goal.

How the classes are put together

The examples N10–N12 at work:

  • sim has a simpars (pars) and a std::vector of particles (parts): composition.
  • particleLJ is a particle: inheritance from a class template, with using for the names of the base class.
  • particle_type is a template parameter: the same sim works with any class of particles that provides a method vij().

Hints: the particles

  • store() saves r in rold, restore() puts it back (a rejected Monte Carlo move); tra_move(delr): \(\mathbf{r} \to \mathbf{r} + \delta\mathbf{r}\).
  • vij(P, L): \(\mathbf{r}_{ij} = \mathbf{r} - \mathbf{r}_P\), then its minimum image (Lab #3), \(r = |\mathbf{r}_{ij}|\), and \(v(r) = 4\epsilon\left[(\sigma/r)^{12} - (\sigma/r)^6\right]\) for \(r < r_c\), 0 otherwise. Correct if \(r_c \le L/2\) (here \(r_c = 5\), \(L/2 \simeq 6.3\)).
  • set_vcut(): vcut \(= v(r_c)\).
  • fij(P, L, vij, vijs, wij) returns the force on this particle due to P, \[\mathbf{F}_{ij} = -\nabla_i v = 24\epsilon\left[2(\sigma/r)^{12} - (\sigma/r)^6\right] \frac{\mathbf{r}_{ij}}{r^2}\] and, through the arguments passed by reference, vij \(= v(r)\), vijs \(= v(r) - v(r_c)\) (the shifted potential, continuous at \(r_c\)) and the virial wij \(= \mathbf{r}_{ij} \cdot \mathbf{F}_{ij}\). For \(r \ge r_c\) all of them are 0.

Hints: energy and PBC

  • calcenergyi(i, opt): the energy of particle i with all the others, \(E_i = \sum_{j \neq i} v(r_{ij})\), with parts[i].vij(parts[j], pars.L). With opt=1, only the particles j > i.
  • totenergy(): \(U = \sum_{i<j} v(r_{ij}) = \sum_i\) calcenergyi(i, 1), each pair once.
  • pbc(i): brings particle i back into the box, centred in the origin: \(\mathbf{r}_i \to \mathbf{r}_i - \mathbf{L} \circ \mathrm{rint}(\mathbf{r}_i \oslash \mathbf{L})\), with \(\circ\) and \(\oslash\) the component-wise product and division: mulcw(), divcw() and rint() of pvector (Lab #3).
  • init_rng(n): n < 0 → rng.rseed() (random seed), otherwise rng.seed(n).

Hints: lattice and snapshots

  • prepare_initial_conf(): a simple cubic lattice of \(N_p = n_x n_y n_z\) particles, parts.resize(pars.Np). One particle in each cubic cell of side \(a\): \(\rho = 1/a^3\), \(a = \rho^{-1/3}\) (cbrt()), \(\mathbf{L} = (n_x a, n_y a, n_z a)\). Particle \((i_x, i_y, i_z)\) at \((i_x a, i_y a, i_z a) - \mathbf{L}/2\) (box centred in the origin), with set_sigma(), set_epsilon(), set_rcut() from pars.

  • save_mgl_snapshot(t): the file cnf-<t>.mgl, one line for each particle, x y z @ radius, with radius \(\sigma/2\). A file is written as std::cout (header <fstream>):

    std::fstream f;
std::string s = "cnf-" + std::to_string(t) + ".mgl";  // the file name
f.open(s, std::ios::out|std::ios::trunc);             // write, from scratch
f << x << " " << y << "\n";
f.close();

The goal: simtest.cpp (1)

project/simtest.cpp

#include "./sim.hpp"
// A class derived from sim, only to test the methods of the
// base class: a derived class can use the protected members
// of sim (as mcsim will do).
template<typename ntype, typename particle_type>
class simtest: public sim<ntype, particle_type>
{
  using bc = sim<ntype, particle_type>;
  using bc::pars, bc::parts, bc::calcenergyi, bc::totenergy,
        bc::pbc, bc::save_mgl_snapshot;
public:
  void run(void) // it hides sim::run()
    {
      ntype V = pars.L(0)*pars.L(1)*pars.L(2);
      std::cout << "Np=" << pars.Np << "  L=" << pars.L
                << "  density=" << pars.Np/V << "\n";

      // tra_move(), store() and restore() on particle 7
      pvector<ntype,3> r7 = parts[7].r, d = {0.1, 0.2, 0.3};
      parts[7].store();
      parts[7].tra_move(d);
      bool moved = (parts[7].r - r7 - d).norm() < 1e-12;
      parts[7].restore();
      bool back = (parts[7].r - r7).norm() < 1e-12;
      std::cout << "tra_move: " << moved
                << "  store/restore: " << back << "\n";
      // vij(), fij() and set_vcut(): particles 0 and 1 are
      // nearest neighbours, at distance a; F must be equal to
      // -grad v (by finite differences), w to r.F
      ntype v, vs, w, h = 1e-6;
      parts[0].set_vcut();
      auto F = parts[0].fij(parts[1], pars.L, v, vs, w);
      pvector<ntype,3> G, Dr = parts[0].r - parts[1].r;
      Dr = Dr - mulcw(pars.L, rint(divcw(Dr, pars.L)));
      for (int k=0; k < 3; k++)
        {
          particle_type P = parts[0], M = parts[0];
          P.r(k) += h;
          M.r(k) -= h;
          G(k) = -(P.vij(parts[1], pars.L)
                   - M.vij(parts[1], pars.L))/(2*h);
        }
      std::cout << "vij(0,1)=" << parts[0].vij(parts[1], pars.L)
                << "  fij: v=" << v << " v-vs=" << v-vs
                << " w=" << w << " |F|=" << F.norm() << "\n";
      std::cout << "F=-grad v: " << ((F - G).norm() < 1e-6)
                << "  w=r.F: " << (fabs(w - Dr*F) < 1e-12) << "\n";

simtest.cpp: how it works

  • simtest is derived from sim only to reach its protected members (using as in N10); simtest::run() hides sim::run(). virtual is not needed: st.run() is called on a simtest object.
  • init_rng(): the same seed twice, the same first number. Lattice: \(N_p = 1000\), \(L = 10\,a = 10 \cdot 0.5^{-1/3} \simeq 12.599\).
  • Particles: particle 7 moved and put back. Particles 0 and 1 are nearest neighbours, \(r = a\) and \(a^6 = 1/\rho^2 = 4\): \(v = 4(1/16 - 1/4) = -0.75\), \(w = 24(2/16 - 1/4) = -3\), \(|\mathbf{F}| = |w|/a\). The force is compared with \(-\nabla v\) computed with vij() by finite differences.
  • Energy: on the lattice all the particles are equivalent, so each one has energy \(E_i = 2U/N_p\) (each pair counted for both particles).
  • PBC: particle 555 is moved by \((L, -L, 2L)\), and pbc() must bring it back.
  • Snapshot: cnf-0.mgl is read back (std::ifstream, a file for reading; std::getline() reads one line, false at the end of the file).

Classic pitfalls

  • The sign of the force: \(\mathbf{r}_{ij} = \mathbf{r}_i - \mathbf{r}_j\), with this as \(i\). With P.r - r the force has the wrong sign: F=-grad v: 0 w=r.F: 0.
  • Each pair counted twice in totenergy() (calcenergyi(i) with opt=0): U/Np is \(-6.78229\), twice the right value.
  • Forgetting j != i in calcenergyi(): particle i interacts with itself at \(r = 0\), and E_0/2 is nan (-nan with some compilers).
  • Forgetting parts.resize(): parts is empty, parts[i] writes outside it: Segmentation fault.
  • The box not centred (sites at \((i_x a, i_y a, i_z a)\)): the energy is the same, thanks to the minimum image, but the site of particle 555, \(\mathbf{L}/2\), is on a face of the box, and pbc() brings it to the opposite face: pbc: particle 555 back to its site: 0.
