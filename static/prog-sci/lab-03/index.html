Soluzione del Laboratorio 02, Task 3: discesa su \(x^2\)

int main() {
    std::cout << "[Task 3] E(x) = x^2, x0 = 1" << std::endl;
    for (int k = 1; k <= 5; ++k) {
        double eta = 0.25 * k;              // int * double: k diventa double
        double x = 1.0;
        std::cout << "eta = " << eta << ":";
        for (int n = 1; n <= 5; ++n) {

        }
        std::cout << std::endl;
    }
    return 0;
}

Soluzione del Laboratorio 02, Task 4: forward e backward

task4_backprop.cpp
#include <iostream>
#include <cmath>

int main() {
    double x = 1.0, y = 1.0;
    double w1 = 1.0, w2 = 1.0;

    // forward
    double z1 = w1 * x;
    double a1 = 1.0 / (1.0 + std::exp(-z1));
    double z2 = w2 * a1;
    double a2 = 1.0 / (1.0 + std::exp(-z2));
    double E  = (a2 - y) * (a2 - y);

    // backward
    double s1 = a1 * (1.0 - a1);            // sigma'(z1) = sigma(1 - sigma)
    double s2 = a2 * (1.0 - a2);            // sigma'(z2)
    double delta2 = 2.0 * (a2 - y) * s2;
    double delta1 = w2 * delta2 * s1;
    double dE_dw2 = delta2 * a1;
    double dE_dw1 = delta1 * x;

Con \(y = 1\) l’errore cala sempre più lentamente e i pesi crescono: \(\sigma(z) = 1\) solo per \(z \to \infty\), quindi nessun peso finito dà \(E = 0\). Con \(y = 0{,}8\) il target è raggiungibile: \(E\) cala di un fattore circa costante ogni 20 passi e i pesi convergono.

Per questo nel framework (Laboratorio 12) i target sono \(0{,}01\) e \(0{,}99\), come nel libro di Rashid, e non \(0\) e \(1\).

Task 1: la funzione ReLU

La Rectified Linear Unit (ReLU) è la funzione di attivazione più usata nel deep learning moderno: \(f(x) = \max(0, x)\). Si scrive con un if: per questo è la prima.

(Nel framework finale implementeremo SigmoidLayer e tanhLayer: la ReLU resta una delle estensioni possibili per il progetto d’esame. Qui serve a scrivere una prima funzione con un if/else, su un caso semplice.)

  1. Nel vostro main.cpp scrivete una funzione double relu(double x).
  2. Implementatela con un costrutto if/else.
  3. Provatela con un numero negativo e uno positivo, stampando i risultati con std::cout.

Task 2: la derivata della ReLU

Nella backpropagation la rete deve calcolare la pendenza, cioè la derivata, della funzione di attivazione. Per la ReLU: \(f'(x) = 1\) se \(x > 0\), altrimenti \(0\). In \(x = 0\) la derivata non esiste: il valore \(0\) è una convenzione.

  1. Scrivete una funzione double relu_derivative(double x).
  2. Implementatela e provatela.

Task 3: la sigmoide e <cmath>

La sigmoide trasforma ogni numero reale in un valore dell’intervallo \((0, 1)\): \(\sigma(x) = \frac{1}{1 + e^{-x}}\).

  1. Includete l’header della libreria matematica standard, il math.h del C: #include <cmath>
  2. Scrivete una funzione double sigmoid(double x), usando l’esponenziale std::exp().
  3. Scrivete la sua derivata, double sigmoid_derivative(double x): \(\sigma'(x) = \sigma(x) \cdot (1 - \sigma(x))\). Conviene calcolare sigmoid(x) una sola volta e salvarlo in una variabile, perché compare due volte.

Task 5: la tangente iperbolica

La terza funzione di attivazione classica, a valori in \((-1, 1)\) e centrata sullo zero: \(f(x) = \tanh(x)\), con derivata \(f'(x) = 1 - \tanh^2(x)\).

  1. Scrivete double tanh_act(double x) usando std::tanh di <cmath>. Il nome tanh da solo non darebbe un errore di compilazione, ed è proprio questo il problema (slide successiva).
  2. Scrivete double tanh_derivative(double x): calcolate std::tanh(x) una volta sola in una variabile e riusatela.
  3. Aggiungete le due colonne alla tabella, o stampate una seconda tabella.

Perché non chiamarla tanh

Compila senza avvisi e termina con un errore in esecuzione

Se scrivete double tanh(double x) { return std::tanh(x); }, il programma compila. In esecuzione termina con Segmentation fault. Il motivo: <cmath> dichiara tanh anche nello spazio dei nomi globale, e std::tanh(double) inoltra la chiamata proprio lì, cioè alla vostra funzione, che richiama se stessa all’infinito, fino all’esaurimento dello stack.

Con -Wall il compilatore lo segnala, warning: infinite recursion detected [-Winfinite-recursion] (da GCC 12, e in clang); senza opzioni g++ non emette alcun avviso, e il programma esce con codice 139. È il primo dei due casi annunciati nel Laboratorio 01 (il secondo è nel Laboratorio 08): si compila sempre con -Wall.

Task 6: verifica numerica

Una derivata sbagliata di un segno o di un fattore 2 non dà nessun errore di compilazione: dà una rete che non impara. Il controllo standard è la derivata numerica a differenze centrali, \(f'(x) \approx \dfrac{f(x+h) - f(x-h)}{2h}\).

  1. Scrivete double sigmoid_numerical_derivative(double x, double h) e l’analoga per la tanh (una funzione per attivazione: passarla come argomento lo vedremo più avanti).
  2. Nel main, con h = 1e-5 e x da \(-5\) a \(5\) a passi di \(0{,}5\) (double x = 0.5 * i;), tenete il massimo errore assoluto std::fabs(analitica - numerica) per ciascuna funzione (fabs come in C).
  3. Stampate i due massimi dopo std::cout << std::scientific; (notazione esponenziale, già in <iostream>) e un [PASS] se entrambi sono sotto 1e-6, [FAIL] altrimenti.

Task 6 (segue): perché proprio \(h = 10^{-5}\)?

  1. Ripetete il confronto in x = 1 per h = \(10^{-1}, 10^{-3}, \dots, 10^{-13}\) e stampate l’errore.

L’errore scende, poi risale, per l’effetto di due errori opposti:

  • per \(h\) grande domina l’errore di troncamento della formula alle differenze centrali, che va come \(h^2\);
  • per \(h\) piccolo domina la cancellazione numerica: f(x+h) e f(x-h) diventano quasi uguali, e sottraendoli si perdono cifre significative.

Il minimo sta dove i due si bilanciano: per la sigmoide e per la tanh, intorno a \(10^{-5}\). È un primo esempio dei limiti della precisione finita del double.

La ReLU resta fuori dalla verifica perché in \(x = 0\) non è derivabile (Task 2).
