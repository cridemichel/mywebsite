Richiamo della Lezione 06

  • Una classe riunisce attributi e metodi. I metodi accedono a tutti i membri; dall’esterno si accede solo a quelli public.
  • I dati si tengono private e si modificano con metodi pubblici che li verificano, come imposta() della classe Temperatura.
  • Il costruttore ha il nome della classe, non ha tipo di ritorno e viene eseguito quando l’oggetto viene creato; può ricevere parametri.

Oggi si vede perché conviene questa organizzazione e che cosa avviene esattamente quando un oggetto viene creato o copiato.

Perché i dati privati: un’interfaccia stabile

Chi usa una classe dovrebbe dipendere solo dalla sua interfaccia pubblica, non dai dettagli interni. Un attributo pubblico entra a far parte dell’interfaccia: se l’autore della classe lo rinomina, il codice che lo usa smette di compilare.

La classe, dopo la modifica:

class Neurone {
public:
1    double peso_sinaptico;
};
1
Prima si chiamava peso.

Il codice che la usa:

int main() {
    Neurone n1;
2    n1.peso = 1.12;
    return 0;
}
2
error: 'class Neurone' has no member named 'peso'.

Con l’attributo privato, un cambio di nome o di rappresentazione interna resta confinato nella classe: è il senso dell’incapsulamento.

Getter e setter

L’accesso ai dati privati passa per metodi pubblici: un getter restituisce il valore di un attributo, un setter lo modifica.

#include <iostream>

class Neurone {
private:
1    double peso_;

public:
2    double getPeso() {
        return peso_;
    }
3    void setPeso(double p) {
        peso_ = p;
    }
};
1
Attributo privato, con il suffisso _ (Lezione 06).
2
Getter: restituisce il valore.
3
Setter: assegna il valore. 
int main() {
    Neurone n1;
    n1.setPeso(1.12);
    std::cout << n1.getPeso();
    return 0;
}

Se peso_ cambia nome o rappresentazione, si aggiornano solo i due metodi: il main resta invariato.

I prefissi get e set sono una convenzione, non una regola del linguaggio.

Setter che verificano i dati

Come imposta() di Temperatura (Lezione 06), un setter può rifiutare i valori non validi.

#include <iostream>

class Persona {
private:
    int eta_;

public:
    void setEta(int nuova_eta) {
1        if (nuova_eta >= 0 && nuova_eta < 150) {
            eta_ = nuova_eta;
        } else {
2            std::cerr << "Errore: età non valida\n";
        }
    }
    int getEta() { return eta_; }
};
1
Controllo di validità: un valore fuori intervallo non viene assegnato.
2
Per ora un messaggio su std::cerr. Le eccezioni, che permettono al chiamante di gestire l’errore, sono l’argomento della Lezione 19.

La lista di inizializzazione

Il costruttore può inizializzare gli attributi prima di eseguire il proprio corpo, con la lista di inizializzazione:

class Neurone {
private:
    double peso_;
    double lr_;

public:
1    Neurone(double peso, double lr) : peso_(peso), lr_(lr) { }
};
1
Dopo i : ogni attributo riceve il valore iniziale, nella forma nome(valore); qui il corpo { } è vuoto.

Per un double il risultato è lo stesso che assegnare nel corpo (peso_ = peso;, Lezione 06). Un attributo che è a sua volta un oggetto, invece, nel corpo viene prima costruito con il costruttore di default e poi riassegnato; nella lista viene costruito direttamente con il valore iniziale.

La lista di inizializzazione: due regole

  • Gli attributi const e i reference devono stare nella lista, perché dopo la creazione non si possono assegnare (la nota sullo scheduler nella Lezione 06).
class Sensore {
private:
1    const double offset_;
public:
2    Sensore(double o) : offset_(o) { }
};
1
Attributo costante: il valore si fissa una volta, alla creazione.
2
Con Sensore(double o) { offset_ = o; } invece: error: assignment of read-only member 'Sensore::offset_'.
  • Gli attributi vengono inizializzati nell’ordine in cui sono dichiarati nella classe, non in quello della lista; se i due ordini differiscono, -Wall lo segnala (-Wreorder).

Più costruttori nella stessa classe

Come per le funzioni (Lezione 05), si può fare l’overloading dei costruttori: quale viene chiamato dipende dagli argomenti.

class Datum {
private:
    double value_;

public:
1    Datum() : value_(0.0) { }
2    Datum(double v) : value_(v) { }
};

int main() {
3    Datum d1;
4    Datum d2(5.5);
    return 0;
}
1
Costruttore di default, senza parametri.
2
Costruttore con un parametro.
3
Chiama il costruttore di default: value_ vale 0.0.
4
Chiama il costruttore con un parametro: value_ vale 5.5.

Il costruttore generato dal compilatore

  • Se una classe non dichiara alcun costruttore, il compilatore ne genera uno di default, che non inizializza gli attributi dei tipi fondamentali (double, int, puntatori): il loro valore resta indeterminato.
  • Se la classe dichiara almeno un costruttore, quello di default non viene più generato. Con il solo Datum(double v), la riga Datum d1; dà error: no matching function for call to 'Datum::Datum()', come per Result nella Lezione 06. Se serve anche Datum d1;, il costruttore di default va scritto esplicitamente.
  • Anche un costruttore può essere private: l’uso tipico, il Singleton, è nella Lezione 13.

Il costruttore di copia e l’assegnazione

Copiare un oggetto mentre lo si crea e assegnargli un valore dopo sono operazioni distinte:

int main() {
    Datum d1(5.5);
1    Datum d2 = d1;
2    Datum d3(d1);
    Datum d4;
3    d4 = d1;
    return 0;
}
1
d2 viene creato come copia di d1: si chiama il costruttore di copia, Datum(const Datum& altro).
2
La stessa operazione, scritta come chiamata esplicita.
3
d4 esiste già: non si costruisce nulla, si chiama l’operatore di assegnazione, operator= (Lezione 10).

Se la classe non li dichiara, il compilatore li genera entrambi: lavorano attributo per attributo, privati compresi. Di un puntatore copiano l’indirizzo, non i dati: con la memoria dinamica (Lezione 08) è un problema, risolto dalla deep copy (Lezione 10).

Il costruttore come conversione

Un costruttore che si può chiamare con un solo argomento definisce anche una conversione: con Datum(double v) il compilatore sa ottenere un Datum da un double, e lo fa anche dove non è scritto.

void stampa(Datum d) { }

int main() {
1    Datum d1 = 2.0;
2    stampa(4.0);
3    d1 = 3.0;
    return 0;
}
1
Equivale a Datum d1(2.0);.
2
Dal double si costruisce un Datum temporaneo, che viene passato alla funzione.
3
Si costruisce un temporaneo con Datum(double) e lo si assegna a d1 con operator=.

Le conversioni implicite possono nascondere errori. Con explicit Datum(double v) le tre righe sopra non compilano; restano ammessi Datum d1(2.0); e static_cast<Datum>(2.0).

Esercizio veloce: il setter

Scrivete una classe Neurone i cui dati siano protetti da un setter.

  1. Due attributi privati: peso_ e lr_ (il learning rate).
  2. I due getter, getPeso() e getLr().
  3. setLr(double): accetta solo valori in \((0, 1]\); altrimenti rifiuta il valore, stampa il motivo su std::cerr e mantiene quello precedente.
  4. Due costruttori, con la lista di inizializzazione: quello di default (peso \(0\), lr \(0{,}1\)) e Neurone(double peso, double lr), che assegna lr_ passando dal setter.
  5. Nel main: provate ad assegnare n.lr_ = 5.0; e leggete il messaggio del compilatore; poi chiamate n.setLr(5.0) e n.setLr(0.05).

Il costruttore con parametri si presta a un errore frequente: se Neurone m(0.7, 99.0); stampa per lr_ un valore privo di senso, la spiegazione è nella slide «Soluzione: lr_ non inizializzato».

Soluzione dell’esercizio: la classe

#include <iostream>

class Neurone {
private:
    double peso_;
    double lr_;

public:
    Neurone() : peso_(0.0), lr_(0.1) {}

1    Neurone(double peso, double lr) : peso_(peso), lr_(0.1) { setLr(lr); }

    double getPeso() { return peso_; }
    double getLr()   { return lr_;   }

    void setLr(double nuovo) {
        if (nuovo > 0.0 && nuovo <= 1.0) {
            lr_ = nuovo;
        } else {
            std::cerr << "[setLr] rifiutato " << nuovo
2                      << ": deve stare in (0, 1]. Tengo " << lr_ << "\n";
        }
    }
};
1
lr_(0.1) inizializza lr_ prima della chiamata a setLr.
2
Se il setter rifiuta il valore, lr_ deve già contenere un valore valido.

Soluzione dell’esercizio: il main

int main() {
    Neurone n;
    // n.lr_ = 5.0;         // <- il compilatore lo rifiuta
    n.setLr(5.0);           // rifiutato in esecuzione, con un messaggio
    n.setLr(0.05);          // accettato
    std::cout << "n: lr " << n.getLr() << "\n";

    Neurone m(0.7, 99.0);   // il costruttore passa dal setter
    std::cout << "m: peso " << m.getPeso() << ", lr " << m.getLr() << "\n";
}
[setLr] rifiutato 5: deve stare in (0, 1]. Tengo 0.1
n: lr 0.05
[setLr] rifiutato 99: deve stare in (0, 1]. Tengo 0.1
m: peso 0.7, lr 0.1

Togliendo il commento a n.lr_ = 5.0;:

error: 'double Neurone::lr_' is private within this context

Soluzione: lr_ non inizializzato

Se dalla lista di inizializzazione si toglie lr_(0.1), lasciando : peso_(peso) { setLr(lr); }, l’uscita diventa per esempio:

[setLr] rifiutato 99: deve stare in (0, 1]. Tengo 6.94378e-310
m: peso 0.7, lr 6.94378e-310

Il setter rifiuta 99 e mantiene il valore di lr_, che nessuno ha inizializzato: il valore è indeterminato e cambia da un sistema all’altro. L’oggetto resta in uno stato non valido.

Il compilatore lo segnala solo con certe opzioni

g++ -Wall        -> nessun avviso
g++ -O2 -Wall    -> warning: 'm.Neurone::lr_' is used uninitialized

L’uso di una variabile non inizializzata si rileva con l’analisi di flusso, che g++ esegue solo quando ottimizza: -Wall da solo non basta. clang++ non lo segnala in nessuno dei due casi.

Esercizi lampo: cosa stampa?

Senza portatile. Si compila con -std=c++17.

1. Quante righe vengono stampate, e quali?

#include <iostream>

class D {
public:
    D()          { std::cout << "default\n"; }
    D(double)    { std::cout << "param\n"; }
    D(const D&)  { std::cout << "copia\n"; }
};

int main() {
    D a;
    D b(1.0);
    D c = b;
    D d = D(2.0);
}

2. La classe Persona della slide «Setter che verificano i dati» non ha costruttori.

Persona p;
p.setEta(200);          // l'età non supera il controllo
std::cout << p.getEta();

Esercizi lampo: le risposte

1. Quattro righe: default, param, copia, param. D d = D(2.0); sembra costruire un oggetto temporaneo e poi copiarlo. Fino al C++14 il compilatore poteva eliminare la copia, ma non era obbligato; dal C++17 in questo caso l’eliminazione è obbligatoria: il temporaneo non viene creato e d è costruito direttamente. Con -std=c++11 -fno-elide-constructors, che vieta l’eliminazione facoltativa, compare una quinta riga, copia.

2. Il valore stampato è indeterminato. setEta(200) rifiuta il valore, ma eta_ non è mai stato inizializzato: leggerlo è undefined behaviour. Verificare i dati nei setter non basta se l’oggetto viene creato in uno stato non valido: per questo servono i costruttori. Incapsulamento e costruttori risolvono due parti dello stesso problema.

Esercizio finale: i layer del framework

Nel framework la rete è una sequenza di layer: un DenseLayer contiene i pesi da addestrare (è un layer parametrico), un SigmoidLayer applica la sigmoide e non ha parametri. Scrivete le due classi con i nomi del framework:

  1. DenseLayer: attributi privati Nnodes (neuroni) e Nin (ingressi), costruttore DenseLayer(int Nn, int Ni) con la lista di inizializzazione, metodo numParametri() che restituisce il numero dei pesi, \(N_\text{nodes} \cdot N_\text{in}\) (il framework, come il libro di Rashid, non usa bias);
  2. SigmoidLayer: senza attributi né costruttori, con numParametri() che restituisce \(0\).

Esercizio finale: i layer del framework (segue)

  1. in entrambe, un metodo descrivi() che stampa il tipo del layer e il numero dei parametri;
  2. nel main, la rete del Laboratorio 12 per MNIST: DenseLayer da 784 a 200, SigmoidLayer, DenseLayer da 200 a 10, SigmoidLayer. Stampate le descrizioni e il numero totale dei parametri.

Soluzione dell’esercizio finale: DenseLayer

#include <iostream>

class DenseLayer {
private:
1    int Nnodes;
    int Nin;

public:
    DenseLayer(int Nn, int Ni) : Nnodes(Nn), Nin(Ni) { }

2    int numParametri() { return Nnodes * Nin; }

    void descrivi() {
        std::cout << "DenseLayer " << Nin << " -> " << Nnodes
                  << ": " << numParametri() << " parametri\n";
    }
};
1
Gli stessi nomi del framework, senza il suffisso _.
2
Un peso per ogni coppia ingresso-neurone.

Soluzione dell’esercizio finale: SigmoidLayer

1class SigmoidLayer {
public:
    int numParametri() { return 0; }

    void descrivi() {
        std::cout << "SigmoidLayer: " << numParametri() << " parametri\n";
    }
};
1
Nessun costruttore: si usa quello generato dal compilatore, che qui non ha attributi da inizializzare.

Nel framework le due classi hanno una base comune, layer, e DenseLayer deriva da ParametricLayer. Qui il totale dei parametri si somma a mano, layer per layer (slide successiva): per raccogliere layer di tipi diversi in un’unica sequenza, come fa Sequential nel framework, serve una classe base comune. È l’argomento della Lezione 12, l’ereditarietà.

Soluzione dell’esercizio finale: il main

int main() {
    DenseLayer   d1(200, 784);
    SigmoidLayer s1;
    DenseLayer   d2(10, 200);
    SigmoidLayer s2;

    d1.descrivi();
    s1.descrivi();
    d2.descrivi();
    s2.descrivi();

    int totale = d1.numParametri() + s1.numParametri()
               + d2.numParametri() + s2.numParametri();
    std::cout << "Totale: " << totale << " parametri\n";
    return 0;
}
